# LangBlue Python AI Learning Engine

A separate Python service for LangBlue's personalized learning intelligence. The existing GitHub Pages frontend and Supabase Edge Functions remain in place; this service is an additive backend, not a frontend rewrite.

## Current foundation

- FastAPI API with typed request/response schemas.
- Supabase Auth token verification before any learner-specific operation.
- Server-only Supabase service-role client; never expose its key to GitHub Pages.
- Every personal learning-record query is scoped by the verified `auth.users.id`.
- OpenAI Responses API adapter, isolated behind a learning-service function.
- CORS allowlist, bounded input sizes, timeouts, and privacy-safe error logging.
- A health endpoint that does not disclose configuration or credentials.

## Run locally

Python 3.11+ is required.

```bash
cd ai-engine
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
cp .env.example .env
# Fill the server-side secrets in .env; never commit it.
uvicorn app.main:app --reload --port 8000
```

Check `GET /health`. The authenticated tutor endpoint is `POST /v1/coach` with a Supabase access token in the Authorization bearer header.

## Important integration notes

1. The browser must send its existing Supabase access token. The API verifies it with Supabase Auth and derives the user ID from the verified token. Do not accept a `user_id` field from the browser.
2. The service-role key belongs only in the Python host's secret manager. The database query still explicitly filters by the verified user ID as defense in depth.
3. The first retrieval adapter reads only `learning_review_items`, a table already present in the LangBlue project. It does not assume that grammar/vocabulary content is stored in a new vector table.
4. The current Supabase project did not report the `vector` extension as installed during initial inspection. Do not run vector SQL or create embeddings until the extension, dimensions, model choice, RLS design, and migration are reviewed.
5. Deploy this service to a Python-capable host (for example, a managed container platform). GitHub Pages cannot run FastAPI. Keep the service URL in frontend configuration, not secrets.

## Roadmap

- Phase 1: connect the existing review records and validate authentication/ownership.
- Phase 2: add a hybrid retrieval layer (Postgres full-text + pgvector) after enabling and migrating the vector extension deliberately.
- Phase 3: add a deterministic spaced-repetition policy and compare it against LangBlue's current review schedule.
- Phase 4: add evaluation fixtures for retrieval quality, groundedness, language-level appropriateness, and privacy isolation. Use RAGAS only after a representative, consented evaluation set exists.
- Phase 5: add streaming, rate limiting, request budgets, tracing, and provider fallback after baseline correctness and cost are measured.

## Security and privacy

- Never log prompts, generated answers, raw learner events, access tokens, or secrets.
- Do not train a shared model on private learner content by default.
- Keep research/analytics consent separate from essential learning functionality.
- Use aggregate or de-identified data for research, with retention limits and documented deletion behavior.
- Configure production HTTPS, host-level rate limits, secret rotation, and monitoring before public release.
